# GHECOM、RBind、Rsite比较协议

固定原940个配体实例、554 PDB、553个独立RNA输入，比较当前RNA-only40、既有fpocketR核心与三个非学习基线。当前模型配置和原报告保持不变。新检测仅接受与原报告SHA256完全一致的RNA输入，不提供原生配体坐标或结合位点标签。

## 方法与来源

**GHECOM**使用作者公开仓库的20260817源码，固定提交`e1950a405323d069673fe2df445ecd3f41e8651e`，直接编译，没有修改源码。使用多尺度`M`模式，网格0.8 Å、小探针1.87 Å、大探针2–10 Å、步长0.5 Å，范德华半径选择Bondi1964（元素半径，避免把RNA当作蛋白残基处理）。保留原聚类和按invRvolume的排序；中心为聚类全部网格点的几何平均。原输出中的`CEN`记录是合成中心，不重复计入网格。20260817版本使用位置参数`M`，其成功路径返回1；包装同时要求没有`#ERROR`、输出文件存在、聚类网格数与元数据一致，不把程序错误当作无候选。

来源：[GHECOM官方说明](https://pdbj.org/ghecom/README_ghecom.html)、[作者源码仓库](https://github.com/kawabata-takeshi/ghecom_test)。这里只评估一个事先固定的多尺度配置，不能将结果推广到GHECOM所有模式和参数。

**RBind**原下载站失效，采用[原论文](https://academic.oup.com/bioinformatics/article/34/18/3131/4987148)的公式复现，不能称为原作者可执行程序的直接运行。核苷酸为节点，非相邻核苷酸存在重原子距离<8 Å时连边；同链观测序列中的相邻节点去除，跨链节点不按编号误删。计算节点度与`(N−1)/Σ最短路径距离`，同时严格超过各自均值加一个标准差的节点为阳性。本次标准差采用样本标准差（ddof=1），不在940例上选择阈值。

复现与[RBinds作者站点](http://zhaoserver.com.cn/RBinds/RBinds.html)的2ZNI公开示例核对：72个节点的节点度完全一致，接近中心性符合官方三位小数精度。该示例验证网络和中心性，不能替代所有边界条件与原二进制的逐例等价验证。

RBind论文的全图距离公式遇到断连图时存在不可达距离。这里保留无穷距离，得到全图closeness为0，不替换为调和中心性或分连通分量的中心性。原始结果记录连通分量数；报告同时提供所有940实例的操作性结果和连通图子集上五方法的匹配比较。全体结果中断连图无候选不是“低化学评分”，其失效来自全图公式的适用边界。

**Rsite**从[作者页面](http://www.cuilab.cn/rsite)下载原始`Rsite_codes.zip`。根据原Python算法，使用每个观测核苷酸的C1′坐标，计算到所有链观测C1′的欧氏距离总和并四舍五入到两位小数。缺少C1′的核苷酸不评分，不用其他坐标替代，不补未观测残基。原Python2生产文件与R消费脚本的列格式和目录不同；这里显式整理为R脚本所需的两个字段（核苷酸索引、距离总和），没有更改数值算法。信号按原Python实现拼接全部RNA链。

最终Rsite结果直接运行未修改的`getGaussianDenoisedExtrema.R`，参数固定为`2 2 1`，使用它输出的极值位置及平滑值。Python移植的初步计算用于流水线检查；R的FFT卷积与Python计算存在末位舍入差异，因此最终分数和排序以原版R输出为准。官方R输出、日志、核对信息保存在`upstream_rsite/`，最终完整五方法结果位于`official_rsite/`。

## 统一空间适配

RBind和Rsite原生输出核苷酸位点，不能将核苷酸直接称为原生空腔。两者采用同一个额外适配器：阳性核苷酸以其重原子几何中心表示，中心距离≤8 Å时空间连边，按单连接连通分量得到区域；每区代表中心为阳性核苷酸中心的平均。它不使用原生配体，不移动中心来提高命中率。

RBind节点排序分数为节点度和closeness两项标准化分数的较小值；区域取节点分数最大值。Rsite节点排序分数为负平滑距离总和，区域取节点最大分数，与原R输出按平滑距离值升序排列极值的方向一致。分数相同时按固定区域编号排序。这些区域化、代表中心和区域排序规则是本评估的适配规则，不是原作者完整口袋生成协议。

三种方法按各自既定顺序进行相同10 Å整残基裁剪，要求至少12个RNA原子，去除裁剪原子集合完全相同的候选，最终最多5个。不因候选少而补充新的启发式中心。无候选保留在同一940实例分母中；检测异常、哈希不一致或输出解析失败直接报错，不当作正常漏检。

## 指标和分类

中心定位和区域覆盖沿用当前统一评估：Top1/3/5中任一中心到原生配体任一重原子最小距离DCA≤4.5 Å为定位命中，裁剪区域覆盖≥80%原生RNA接触原子为覆盖命中。原生RNA接触阈值为4.5 Å。距离统计明确区分有候选与无候选，缺失距离不填0。

提供总体、实验方法、RNA总观测长度、最长观测链、链数、X-ray分辨率、电镜分辨率、NMR类型以及实验方法×长度分组。沿用[分类评估协议](pocket_stratification_protocol.md)的边界和RNA冗余分组；NMR仍使用首模型。提供整RNA组5000次配对bootstrap；该数据已用于研发，结果不是新独立测试。

RBind、Rsite另计算未空间适配的原生核苷酸Precision、Recall、MCC。真值是同一RNA输入中所有纳入配体的4.5 Å接触核苷酸并集，每个独立RNA输入统计一次，避免其他已知结合位点被当作同一实例的假阳性。未纳入和未发现的位点仍可能造成标签不完备；这些数值也不是原论文自己的数据和标签协议。无预测时Precision无定义，分母退化时MCC无定义，明确保存为null。

JSON中`paired_vs_ours.<method>`以当前方法为参考。复用两方法统计函数时，其内部`methods.fpocketr_core`是对照槽，实际对应外层的`<method>`；总体和分组方法指标保留真实方法名称。

## 本次完成结果

最终使用原版Rsite R输出，940个实例的定位命中结果如下。百分比的分母均为940，无候选也计入分母。

| 方法 | Top1 | Top3 | Top5 | Top5接触覆盖≥80% |
|---|---:|---:|---:|---:|
| RNA-only40 | 314（33.4%） | 565（60.1%） | 652（69.4%） | 647（68.8%） |
| fpocketR核心 | 238（25.3%） | 387（41.2%） | 428（45.5%） | 397（42.2%） |
| GHECOM多尺度 | 102（10.9%） | 207（22.0%） | 211（22.4%） | 280（29.8%） |
| RBind公式复现＋空间适配 | 49（5.2%） | 101（10.7%） | 124（13.2%） | 236（25.1%） |
| Rsite原算法＋空间适配 | 50（5.3%） | 158（16.8%） | 217（23.1%） | 326（34.7%） |

NMR的74例中，GHECOM Top5为58/74（78.4%），高于fpocketR的40/74（54.1%）；当前方法为72/74（97.3%）。长度>1000 nt的8例中，GHECOM和RBind各命中1例，当前方法没有命中；这一小组只能作描述，适合检查各方法的互补漏检，不能作为总体排名的依据。

12个独立RNA输入对应31个实例的RBind图断连。其余909个连通图实例上，当前方法、fpocketR、GHECOM、RBind适配、Rsite适配的Top5分别为70.7%、46.4%、22.9%、13.6%、22.8%。RBind的全体低命中率不能仅由断连解释；空间适配与统一小分子中心定位任务亦不同于原生核苷酸功能位点任务。

原版R与Python诊断计算的末位平滑差异最大为0.01，在553个RNA中改变了2个输入的极值集合、1个输入的入选空间区域；最终总体Top1/3/5未变化。核苷酸层面的TP/FP/FN/TN按每个独立RNA统计一次再汇总，Precision、Recall、MCC为核苷酸micro统计，较长RNA贡献更多核苷酸，不能理解为逐RNA等权平均。

源码、结构、原始程序输出和最终分组计数已核对；当前方法与fpocketR的940条原指标字典逐例保持一致。全套330项测试通过。第一次汇总的元组/列表类型错误已修复，并增加首次检测与缓存复用的身份一致性回归测试；原检测契约、原脚本和原检测记录保存在`initial_detection_provenance/`，`cache_transfer.json`记录检测记录仅契约字段更新且RNA、GHECOM日志与网格输出哈希不变的复用过程，没有重新选择方法参数。

## 运行和文件

需要项目Python依赖、C编译器、make，以及原版R脚本所需的Rscript；R脚本只使用基础R。

```bash
python scripts/install_classical_pocket_tools.py
python scripts/compare_classical_pockets.py --workers 4
python scripts/verify_classical_pockets.py
```

前两步下载并校验固定源码、编译、检测和生成初步结果。第三步必须执行：它运行原版R，使用原版R的核苷酸与排序分数重新评估Rsite，生成最终五方法比较。不要把第二步Python数值移植的初步Rsite结果当作最终结果。

默认输出根目录`outputs/hariboss_pocket_classical_v5/`包含检测缓存、原输入与程序日志、契约及核对信息。最终可读报告为`official_rsite/summary.md`，该目录同时含`comparison.json`、`summary.json`、`metrics.csv`、`residue_metrics.json`、`rsite_pools.json`及`contract.json`、`verification.json`。数据成员、结构、源码或二进制哈希不符时停止，不自动忽略或更新契约。

断点重运行第二步时只复用契约一致、原始输出哈希正确的完成RNA检测。第三步复用的R输出亦逐例与固定输入关联，最终契约记录R源文件、R版本、原输出及评估实现的哈希。
